# 档案元数据核对台

`sologsb-1020` 是一个用于口述史/手稿元数据比对与碑帖拓片版本回传对账的本地优先前端工作台，使用 Qwik、TypeScript 和 Qwik UI 构建。

包含两个工作台（左下角浮动切换，选择保存在本地）：

- **碑帖拓片版本比对台**（默认）：外场编目组带回版本比对包后的回传对账。
- **档案元数据核对台**：原有的 A/B 两组记录匹配、逐字段合并与审计。

## 碑帖拓片回传对账

外场包按拓片号、摹刻批次、原石和扫描指纹登记，本台负责合并结论、字段选择与审计：

- **稳定编号挂回**：优先用包内 `stableNo` 挂回原记录；本机改过拓片号也不错配，缺失时按扫描指纹、再按拓片号+批次兜底，挂接别名全程留痕。
- **分歧并列保留**：纸张、拓工、钤印出现分歧时，各来源说法并列保留并生成待裁项；确认/裁决前不覆盖正式字段。
- **已确认结果保护**：记录一旦确认（锁定），后续回传只追加候选，不覆盖任何已确认结果；已裁决字段收到新说法时重新挂起，但正式值不变。
- **中断可续跑、重试幂等**：每份包有入账回执（进度、已处理条目幂等键），写入中断后再次导入同一包即从断点续跑，重试整包只跳过、不重复建档、不重复开单。
- **旧版包可导入**：v1 包（`stable_id/batch/stele/scan_hash/paper_type/artisan/seals_text`，钤印自由文本）自动迁移为 v2，钤印拆成印文+位置的结构。
- **导出闸门**：待裁项全部处理完（裁定或搁置）后才允许更新导出包，导出含台账结论、裁决记录与全部包回执。

v2 包示例：

```json
{
  "packetId": "PK-2026-0928-FIELD",
  "schemaVersion": 2,
  "exportedAt": "2026-09-28T09:30:00.000Z",
  "source": "外场编目组（碑林一组）",
  "entries": [
    {
      "stableNo": "STB-1824-0032",
      "rubbingNo": "拓甲-0145",
      "copyBatch": "道光四年摹刻批",
      "stone": "《玄秘塔碑》原石（西安碑林）",
      "fingerprint": "sha256:9f2c41a7e8",
      "paper": "宣纸",
      "rubber": "乌金拓",
      "seals": [{ "text": "端方之印", "position": "右下" }]
    }
  ]
}
```

## 档案元数据核对台

- 导入 A / B 两组记录，支持 JSON 数组、制表符和竖线分隔文本。
- 按标题、日期、人物、地点和编号加权匹配，显示综合分数与判断依据。
- 键盘密集复核：J/K 移动、Enter 合并、C/R 确认或忽略，支持批量操作。
- 合并时逐字段并排展示 A / B 来源，每个冲突字段可单独保留或拼接。
- 保存原始记录、字段来源选择、合并结果和忽略动作，形成完整审计轨迹。
- 支持撤销重做、离线 localStorage 保存和 JSON 核对包导出。
- 大量记录采用分批窗口渲染，匹配计算限制每条记录的候选数，避免一次挂载全部行。

## 技术栈

- Qwik 1.20
- TypeScript 5.9
- Qwik UI Headless `@qwik-ui/headless`
- Vite 7

## 开发

```bash
npm install
npm run dev
```

开发服务使用 Vite 默认端口，不在源码中硬编码宿主端口。

## 生产构建

```bash
npm run build
npm run preview
```

静态产物输出到 `dist/`。

## Docker

```bash
docker build -t sologsb-1020 .
docker run --rm -p 10020:80 sologsb-1020
```

nginx 在容器内监听 `80`，宿主端口 `10020` 由根端口表或运行命令映射。

## 数据说明

记录和审计轨迹保存在当前浏览器。导入新记录后自动重新计算候选匹配，但不会自动确认或覆盖任何字段。
